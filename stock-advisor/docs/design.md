# stock-advisor 設計書 — コンセプト・ルール・リスクヘッジ（2026-10-17）

2時間ぶんの考えを、結論から順に書く。迷った点と、選ばなかった案も残す（あとで見直すため）。

## 0. 結論（先に）

- **このツールは「当てる」道具ではなく、「負けない形を守る」道具。** 期待できるのは、上げ相場にそこそこ乗り、暴落で大けがをしない、そして毎回の判断を記録して反省できること。個別株を5つ選んで指数に勝ち続けることは期待しない
- **土台（コア）は指数のインデックス投資、このツールは衛星（サテライト）。** 資産の大半は全世界か日本の指数に積み立て、このツールには「全部失っても生活が変わらない額」だけ入れる
- ルールは **4層の守り**（地合い → 銘柄 → 集中 → 口座）で、どれか1つが外れても破滅しない構造にする
- **自動化の順番**: 候補を出す（できた） → 紙上で回す（できた） → 日々の退出ルールと月次の入れ替えを自動で回す（今回） → 3か月の紙上の成績を見てから、実際の発注をつなぐか決める

## 1. コンセプト

### 1-1. 何のためのツールか

人は、上がっている株を高値で買い、下がると怖くなって底で売る。これは知識の問題ではなく、感情と構造の問題。だから「どの株か」より「**いつ買い、いつ退き、いくら入れるかを、事前に決めた規則で機械的にやる**」ことに価値がある。ルールを決めて守ることは、ムートンの「読むだけでは変わらない。行動して記録する」と同じ姿勢。

### 1-2. 何を根拠に「エッジ」があると考えるか

長い期間・多くの市場で確認されている規則性は少ない。使うのは次の2つだけ。

| 規則性 | 内容 | 主な根拠 |
|---|---|---|
| モメンタム | 過去6〜12か月に上がった株は、その後3〜12か月も相対的に上がりやすい | Jegadeesh & Titman (1993)、Asness ほか "Value and Momentum Everywhere" (2013) |
| トレンド追随 | 価格が長期移動平均より上のときだけ持つと、リターンはあまり落ちず最大下落が大きく減る | Faber (2007) "A Quantitative Approach to Tactical Asset Allocation" |

正直な前提:
- どちらも「**平均的には**」の話で、何年も効かない期間がある（モメンタムは2009年の反転局面で大きく負けた）
- 日本の大型株67銘柄・上位5つという小さな設定では、ばらつきが大きい。バックテストの数字を信じすぎない
- **モメンタムが実データで効いていなければ、このルールは「均等の買い持ちより年2ポイント悪く、下落は4倍」の道具になる**（合成データでの検証、5-2 の5回目）。だから実データのバックテストと紙上の成績を見てから使う
- 手数料は主要ネット証券で0円でも、スプレッドと税金（20.315%）はかかる。月1回の入れ替えは税の繰り延べを捨てる行為で、長期の指数積み立てより不利になりやすい

### 1-3. 指数に勝てないかもしれないのに、なぜやるか

1. **最大下落を抑える**ため。日経平均の買い持ちは2008年に −60%、2020年に −30% の下落があった。地合いのルールで現金に逃げると、下落の深さを減らせる（代わりに戻りの初期を取り逃す）
2. **自分の判断を記録して、改善できる形にする**ため。裁量の売買は、なぜ勝ったか負けたかが分からない
3. 衛星として小さく回すなら、負けても学びが残り、勝てばコアを補う

## 2. ルール（決めたこと）

### 2-1. 売買の規則

| 層 | 規則 | 値 | なぜ |
|---|---|---|---|
| 地合い | 日経平均が200日移動平均より上のときだけ株を持つ。下なら全部現金。判定は月1回の入れ替え日 | 200日 | Faber の10か月線と同じ発想。毎日判定するとダマシで往復するので、月1回だけ |
| 銘柄の条件 | 株価が自分の200日線より上、年率の変動率が60%以下、12-1モメンタムがプラス | 200日・60% | トレンドが上向きの銘柄だけ。変動率の上限は、1つの銘柄で口座が壊れるのを防ぐ |
| 並べ方 | 12か月の値上がり率（直近1か月を除く）が高い順 | 252日・21日除外 | 学術研究の標準。直近1か月を除くのは、短期の反転（1か月リバーサル）を避けるため |
| 銘柄数 | 上位5銘柄、同じ金額ずつ | 5 | 10にしたいが、単元株100株と数百万円の資金では買えない銘柄が出る。5は「分散」と「買える」の妥協点 |
| 業種の上限 | 同じ業種は2銘柄まで | 2 | モメンタムは業種で固まる（2024年の半導体など）。固まると「5銘柄」が実質1銘柄になる |
| 入れ替え | 月の最初の営業日に判断し、翌営業日の終値で約定。残る銘柄は目標比率から ±25% 以内なら触らない | 月1回・±25% | 週1回だと売買コストと税が増え、年1回だとトレンドの変化に遅れる。月1回がモメンタム研究でも標準 |
| 退出（毎日） | 保有銘柄が自分の200日線を割ったら翌日に売る。または取得値から −20% で売る。売った分は次の入れ替えまで現金 | 200日・−20% | 月に1回しか見ないと、決算ショックや不祥事で −30% を月内に食らう。「入る条件が崩れたら出る」のが最も規則として一貫する。−20% は最後の保険 |
| 口座の遮断器 | 戦略の評価額が直近の最高値から −20% になったら全部売って**止める**。紙上の運用でも、人が理由を見て `paper resume` するまで再開しない | −20% | 想定外（ルールが効かない相場、データの異常、自分のバグ）を疑う機会をつくる。自動で再開しない |

### 2-2. 資金の規則（コードの外で守る）

- このツールに入れるのは、投資できる資産の **20%以下**、かつ全部失っても生活が変わらない額
- 現物のみ。**信用取引・レバレッジ・空売りはしない**。コードにも書かない
- NISA はこのツールに使わない（売ると枠が翌年まで戻らないので、月1回の入れ替えと相性が悪い）。NISA は指数の積み立てに使い、このツールは特定口座（源泉徴収あり）で回す
- 新規の資金追加は月1回の入れ替え日だけ。損が出ているときに「取り返すために」足さない

### 2-3. 運用の規則（自動化してよい範囲）

| 段階 | 自動でやること | 人がやること |
|---|---|---|
| いま（紙上） | 平日の引け後に候補を出す。保有の退出ルールを毎日確かめる。月初に紙上で入れ替える。全部 `reports/` と `data/paper-portfolio.json` に残す | 月に1回、紙上の成績とバックテストを見比べる。遮断器が動いたら理由を調べて再開を決める |
| 3か月後に判断 | （紙上の成績がバックテストと大きくずれなければ）証券会社の API に接続 | 接続の判断。発注の上限額・1日の発注回数の上限をコードに固定する。鍵は環境変数 |
| 実運用 | 指値で発注（成行は使わない）。発注前に「今日の発注合計 ≤ 上限」「保有銘柄数 ≤ 5」「現金がマイナスにならない」を機械で検査 | 毎週、約定の記録と紙上の計算が一致しているか見る。ずれたら止める |

## 3. リスクヘッジ（何が起きたら、どう守られるか）

| リスク | 起きること | 守り |
|---|---|---|
| 暴落（2008・2020型） | 指数が −30〜−60% | 地合いのルールで現金へ。遅れて入る代わりに底は食らわない。遮断器が最後の壁 |
| 個別株の事故（決算・不祥事） | 1銘柄が1日で −20〜−30% | 1銘柄は資金の約20%なので口座では −4〜−6%。翌日に退出ルールで売る。変動率の上限で荒い銘柄は最初から外す |
| 業種の一極集中 | 5銘柄が全部半導体で、同時に下がる | 同一業種2銘柄まで |
| ダマシ（往復びんた） | 200日線をまたいで売買を繰り返す | 地合いは月1回だけ判定。銘柄の退出は200日線割れだけ（線の上に戻っても次の月初まで買い直さない） |
| モメンタムの反転 | 底打ち直後、負けていた株が急騰し、勝っていた株が置いていかれる | 完全には防げない。地合いのルールで現金にいる間に起きることが多いので、取り逃すだけで損はしにくい |
| 過学習 | 過去に合わせた値が、将来は効かない | `backtest --sweep` で隣の値（上位3/5/8、6か月/12か月、150/200/250日）を並べ、結果が値で大きく変わるなら疑う。値はいじらず、研究の標準値を使う |
| データの異常 | 株式分割の未調整、欠損、誤った終値 | 調整後終値を使う。欠損した銘柄はその日の対象から外す。1日で ±30% 以上動いた銘柄は警告して人が確認する（次の課題） |
| 自分のバグ | 売り買いが逆、株数の桁違い | 先読みなし・単元株・現金不足・注文の統合のテスト。紙上で3か月。実発注は上限額を固定 |
| 実行の失敗 | 発注が通らない、約定しない | 指値なので約定しないことはある。翌日の引け後に再評価して出し直す（追いかけない） |
| 心理 | 下がっているときに規則を破りたくなる | 規則は書いてある。破るなら「破った」と記録する。遮断器が動いたら、再開の理由を文章で書いてから再開 |

## 4. 選ばなかった案（と理由）

- **ランキングを「モメンタム ÷ 変動率」にする**: やや改善するという研究もあるが、パラメータが増える。変動率は上限として使うだけにした
- **逆ボラティリティで配分する**: 5銘柄・単元株では配分の精度が出ない。同額でよい
- **複数の期間（3・6・12か月）の平均で並べる**: 過学習への備えとしては良いが、まず標準の12-1で紙上の成績を見る。次の候補
- **毎週の入れ替え**: コストと税で負ける可能性が高い。`--freq W` は検証用に残す
- **地合いにヒステリシス（±2%の帯）をつける**: ダマシを減らすが、月1回判定で十分と判断。紙上で往復が目立てば足す
- **トレーリングストップ（高値から −15%）**: 200日線割れとほぼ同じ役目で、パラメータが増えるだけ。取得値 −20% の保険だけ残す
- **ショート・両建て**: 個人では借株のコストと無限の損失リスクが見合わない
- **AI による銘柄予測**: 検証できない。この設計は「予測しない」ことが前提

## 5. ツールの評価のしかた（3か月後に何を見るか）

1. `backtest --start 2010-01-01` と `--start 2015-01-01`: 年率リターンが日経平均の買い持ちと同程度以上か、最大下落が小さいか。**両方とも負けていたら、このルールは使わない**（指数を買えばよい）
2. `backtest --sweep`: 隣の値で結果が大きく崩れないか
3. 紙上の3か月: 月次のリターンが、同じ期間のバックテストと符号・大きさで大きくずれていないか（ずれ = 実装か仮定が違う）
4. 退出ルールが動いた回数と、その後の値動き: 退出して正解だった割合。半分以下なら −20% の値を見直す
5. 遮断器が動いたら、その時点で一度すべてを見直す

## 5-2. 検証と改善の記録

「検証 → 直す」を繰り返した記録。何を疑い、何が見つかり、どう直したか。

| 回 | 疑ったこと | 見つかったこと | 直したこと |
|---|---|---|---|
| 1 | 極端な相場・壊れたデータで落ちないか | 上場廃止（株価が NaN）になった保有銘柄が、永遠に保有され続ける | 5営業日とれなければ最後の値で退出扱い（`max_missing_days`）。人が確かめるよう警告 |
| 1 | 同じ業種の上限が効いているか | 効いていた（地合いが弱い日で検証していたため、最初のテストが甘かった） | 地合いなしで厳密に検証するテストに差し替え |
| 2 | バックテストが楽観的すぎないか | 判断した日の終値で約定していた。実際は引け後に注文し、翌日に約定する | 既定を「翌営業日の終値で約定」に変更（`--lag`）。紙上の口座も注文を1日待たせて翌日の終値で約定 |
| 2 | 退出の予定と入れ替えが同じ日にぶつかる | 紙上の口座で、退出の売りが入れ替えの注文に上書きされて消えることがあった | 入れ替えの目標に残る銘柄の退出は取り消す（バックテストと同じ扱いにそろえた） |
| 2 | 注文の作成が壊れた状態を作らないか | ランダムな口座・株価300通りで検査。壊れなし | 不変条件（同一銘柄1注文・単元の倍数・現金不足なし・対象外が残らない）をテストに固定 |
| 2 | 株価のキャッシュが週末に毎回取り直される | 「1日以内」で判定していたので土日・月曜の朝に取り直していた | 前の営業日の終値まであれば新しいとみなす。取り直しは3回まで再試行、失敗時は古いキャッシュで動かして警告 |
| 2 | 誤データ（分割の未調整など）に気づけるか | 気づけなかった | 直近60日で ±30% の値動き・株価がとれない・履歴が短い銘柄を「データの確認が必要」として毎回出す |
| 2 | 退出ルールが役に立っているか分からない | 回数しか出ていなかった | 「退出して正解だった割合」（売った後21営業日で下がった）と年ごとの表を追加 |

| 3 | 多数の乱数シードで CLI が落ちないか、速度 | 20 シードで失敗なし。67銘柄×16年のバックテストは3秒 | — |
| 4 | **バックテストと紙上の口座が同じ判断をするか**（同じデータで突き合わせ） | 遮断器が入れ替え日に動くと、バックテストはその日のうちに買い直していた（「止めて人が見る」に反する）。紙上の手順も CLI と長期シミュレーションで別々に書かれていた | 遮断器が動いた日は入れ替えしない。紙上の1日の手順を `engine.py` に一本化し、CLI も長期シミュレーションも同じ関数を使う。遮断器なしで評価額の差 1% 未満、ありでも 6% 未満（しきい値ぎりぎりの1日差）をテストに固定 |
| 4 | 同じ日に2回 `paper auto` を回すと二重に約定しないか | しない（判断した日と同じ日の約定待ちは約定させない） | テストに固定 |

| 5 | ルールは「狙った効果」を本当に拾うか | モメンタムを埋め込んだ合成データでは、均等の買い持ちに 8/8 で勝つ（年率 +27% vs +9%）。**純粋なランダムウォークでは 2/8 しか勝てず、年率で約2ポイント負け、最大下落は4倍**（−24% vs −5%。5銘柄に集中するコスト） | 実装がモメンタムを拾うことと、地合いの判定が下げ相場で最大下落を半分にすること（−15% vs −32%）をテストに固定。「モメンタムが実データで本当に効いているか」が全て、という認識を 1-2 に追記 |
| 5 | コストが3倍・5倍でも成り立つか | 未確認（実データ待ち） | `backtest --sweep` にコスト0.3%・0.5%の行を追加 |

| 6 | 入れ替えのたびに「比率を下げる 15株」のような無駄な売買が出る | 出ていた（単元株では約定できない大きさの調整も含む） | 残る銘柄は目標比率から ±25% 以内なら触らない（`rebalance_band`）。バックテストと紙上の口座の両方に同じ規則を入れ、突き合わせテストが通ることを確認。`--sweep` に「毎回均等に戻す」の行 |

まだ検証できていないこと: **実データでの成績**（この作業環境から株価がとれない）。手元で `backtest --start 2010-01-01 --sweep --by-year` を回すのが次の検証。
